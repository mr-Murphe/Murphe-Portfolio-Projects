# AUTO SAVE PROTOCOL

When Murph says **"auto save"**, treat it as a command to reconcile the meaningful work from the current conversation into durable external project state and assets.

## Required actions

For every relevant project touched in the thread:

1. Review the current conversation since the last known durable save and identify meaningful project changes.
2. Update the relevant `PROJECT_STATE.md` with:
   - current phase
   - overall completion
   - current-stage completion
   - completed work
   - decisions
   - blockers
   - next actions
   - next stage
   - parking-lot ideas
   - last-updated date
   - change log
3. Save or upload important finalized assets created in the conversation to the correct Google Drive project folder when Drive access is available.
4. Prefer canonical/final assets over every intermediate draft.
5. Preserve provenance and status. Do not relabel an uncertain or intermediate artifact as final.
6. If an asset cannot be transferred, record its existence, source, status, and recovery limitation in project state.
7. For code-heavy projects, update GitHub handoff/project documentation when the change is public-safe and useful to Codex or other agents.
8. Never publish private personal or employer-confidential material into a public repository.
9. Update the central portfolio only when priority, project status, stage, or meaningful completion actually changed. Mere activity does not justify reprioritization.
10. Avoid duplicate canonical files. Preserve one clear source of truth and archive/supersede older versions when appropriate.
11. Report concisely what was saved, what project state changed, and any limitations or unsaved items.

## Meaning

**Auto save = reconcile this conversation into durable external project state and assets.**
